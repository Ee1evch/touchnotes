# Решения, принятые по ходу работы

## Окружение и сборка

- **Локально нет Android SDK, а `dl.google.com` и `maven.google.com` закрыты сетевой политикой среды**, где писался
  код. Поэтому собрать APK на месте нельзя. Настоящая сборка идёт в GitHub Actions (`.github/workflows/build.yml`):
  тесты → `assembleDebug` → артефакт `nastavnik-debug-apk`. Логику без Android (SSE, сборка запроса, ошибки,
  парсер чистовика, маркер `[[ГОТОВО]]`) я дополнительно гонял локально в отдельной JVM-сборке. HTML-шаблоны
  (чат, чистовик A4, графики) проверял в Chromium через Playwright по встроенному примеру.
- В workflow не используется `android-actions/setup-android`: эта версия ставит удалённый пакет `tools` и падает.
  SDK на раннере `ubuntu-latest` уже установлен.
- **Версии:** AGP 8.10.1, Gradle 8.14.3, Kotlin 2.2.21, KSP 2.2.21-2.0.4, Compose BOM 2025.06.00,
  `compileSdk`/`targetSdk` 36, `minSdk` 29, JDK 17. Это проверенная совместимая связка. Новее не брал: из среды
  нельзя было посмотреть список версий в Google Maven. Обновление до AGP 9 — отдельная задача.
- **Общий debug-ключ** `app/debug.keystore` лежит в репозитории (пароль `android`). Без него каждая сборка в CI
  подписывалась бы новым ключом, и `adb install -r` поверх старой версии не работал бы. Ключ не секретный
  и годится только для отладочных сборок.

## Несколько нейросетей

- Провайдеры: **Anthropic Claude**, **Google Gemini** (нативный API `generativelanguage.googleapis.com/v1beta`,
  стрим `streamGenerateContent?alt=sse`, ключ в заголовке `x-goog-api-key`, а не в адресе) и
  **OpenAI-совместимый** (`/chat/completions` с `Authorization: Bearer`). Третий вариант закрывает OpenAI,
  OpenRouter, агрегаторы «много моделей по одному ключу» и свои серверы.
- Четвёртый — **Anthropic-совместимый прокси** (Claudex, CLIProxyAPI, claude-max-api-proxy): тот же клиент
  Claude, но с адресом из `ANTHROPIC_BASE_URL`, необязательным ключом и «чистым» телом запроса — без
  `output_config`, `fallbacks` и beta-заголовков, которых прокси могут не понимать. Ключ проверяется через
  `GET /v1/models`. Адрес нормализуется (`/v1`, `/v1/messages`, хвостовые `/` обрезаются).
- Заголовок авторизации для прокси выбирается (`AuthMode`): по умолчанию **оба** — `x-api-key` и
  `Authorization: Bearer`. Claude Code с `ANTHROPIC_AUTH_TOKEN` шлёт Bearer, с `ANTHROPIC_API_KEY` — x-api-key,
  и прокси принимают то или другое; два заголовка с одним токеном работают в обоих случаях.
- **Вставка настроек из буфера** (`ProxyConfigParser`): понимает `export`/`set`/`$env:`, JSON из
  `settings.json`, переменные `ANTHROPIC_*`, `OPENAI_*`, `GEMINI_API_KEY`, а также просто «адрес + ключ».
  Тип угадывается по переменным, по `/proxy/` в адресе или по префиксу ключа (`AIza`, `sk-ant-`).
- Обычный `http://` разрешён во всех сборках (`network_security_config`): прокси в домашней сети почти всегда
  без TLS. Для адресов не на localhost в настройках показывается предупреждение. Доверяю также
  пользовательским сертификатам — для прокси с самоподписанным https.
- Общий интерфейс `AiBackend` (стрим, обычный ответ, проверка ключа, список моделей). Промты, история,
  маркер `[[ГОТОВО]]`, чистовик и ошибки общие для всех. Подсказки в ошибках называют сайт нужного провайдера.
- Ключи и модели хранятся **отдельно для каждого провайдера**: переключение туда-обратно ничего не теряет.
  Ключ Claude из первой версии подхватывается автоматически.
- Названия моделей у Google и OpenAI меняются часто, поэтому для Gemini по умолчанию стоят «плавающие»
  `gemini-flash-latest` / `gemini-pro-latest`. Для всех провайдеров есть «Загрузить список моделей»
  (`GET /models`) с поиском и поле «своя модель».
- Gemini: «мысли» модели (`thought: true`) в ответ не попадают, но показывают «Наставник думает…»;
  блокировка (`promptFeedback.blockReason`, `finishReason: SAFETY`) превращается в понятный отказ.
  Для чистовика включён `responseMimeType: application/json`.
- OpenAI-совместимые: лимит токенов не передаю. Сервисы ждут разные поля (`max_tokens` или
  `max_completion_tokens`), и неподходящее даёт ошибку 400. По той же причине не включаю `response_format`
  для чистовика: его выручает терпимый парсер JSON. Адрес, вставленный целиком (с `/chat/completions`),
  исправляется сам.
- Какая нейросеть отвечает, видно на главном экране («Нейросеть: Gemini»).

## Claude API

- Запросы через **OkHttp напрямую** (без Java SDK), как в задании. SSE разбирается своим парсером (`claude/Sse.kt`).
- Модели: по умолчанию `claude-sonnet-5-5`, на выбор `claude-haiku-5-5` и `claude-opus-5-5`. Чистовик по умолчанию
  тоже на Sonnet 5.5.
- `output_config.effort = "medium"`. Thinking не задаю, у этих моделей по умолчанию включено адаптивное мышление.
  Пока модель думает, в чате видно «Наставник думает…». `temperature` не передаю (новые модели его отвергают).
- `max_tokens = 16000` и для наставника, и для чистовика: размышления тоже тратят этот лимит. Короткий ответ
  обеспечивает промт («до 120 слов»), а не обрезка. Если ответ всё же упёрся в лимит, в конце пишется «(ответ обрезан)».
- **Серверный резерв при отказе модели:** для Sonnet и Opus добавлены `fallbacks: "default"` и заголовок
  `anthropic-beta: server-side-fallback-2026-07-01` (Anthropic рекомендует это для новых моделей; для Haiku резерва
  нет). Если сервер вернёт 400 из-за этого параметра, клиент один раз повторит запрос без него и больше его
  не шлёт. Если ответ всё-таки «отказ» (`stop_reason: refusal`), студент видит понятное сообщение.
- Один автоматический повтор при 529/5xx, но только пока ничего не напечатано. 429 не повторяется: показываю,
  сколько подождать (из `retry-after`).
- Проверка ключа в настройках — бесплатный `GET /v1/models/{модель}`. Он проверяет и сам ключ, и доступность
  выбранной модели.
- Картинки уходят только в последнем сообщении. В прошлых сообщениях вместо картинки пометка
  «[к этому сообщению был приложен снимок экрана]», чтобы модель понимала контекст. Сообщения-ошибки
  в историю для модели не попадают. Подряд идущие реплики одной роли склеиваются (API требует чередования).
- `{STRICTNESS}` в промте заменяется не просто названием, а пояснением: «подсказки — короткая подсказка
  направления…». Так модель лучше держит режим.
- Промт чистовика передаётся как `system`, а в `user` идут снимки и фраза «Вот N снимков… по порядку».
  Повторная попытка — тот же запрос с припиской «Верни только валидный JSON».
- **Терпимый JSON:** вырезаю от первой `{` до последней `}`, разрешены висячие запятые и числа вместо строк.
  Если модель не удвоила `\` в LaTeX, одиночные обратные косые черты чинятся автоматически (`\frac` → `\\frac`).
  Настоящие `\n` перед кириллицей при этом не трогаются. Неизвестные типы блоков отбрасываются.
- Маркер `[[ГОТОВО]]` распознаётся и с пробелами, и в любом регистре. Пока ответ печатается, недописанное
  начало маркера в конце текста («[[ГОТ») скрыто, чтобы не мигало.

## Плавающая кнопка и стилус

- Окно кнопки: `TYPE_APPLICATION_OVERLAY`, `FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL`.
- **Стилус «насквозь».** Одно касание нельзя передать окну ниже, Android так не умеет. Поэтому кнопка ловит
  наведение пера (hover, перо видно ещё до касания) и касание стилусом/ластиком. В ответ окно на 1,5 с получает
  `FLAG_NOT_TOUCHABLE`, и следующие штрихи уходят в Touchnotes. Если перо не умеет hover, самое первое касание
  стилусом по кнопке «съедается», но кнопку не нажимает.
- **Прозрачность кнопки ограничена 80%.** Android 12+ блокирует касания, проходящие сквозь чужое окно, если оно
  непрозрачнее 0,8. В настройках можно 30–80%.
- Положение запоминается как сторона + доля высоты экрана, поэтому переживает поворот.
- Долгое нажатие открывает меню в отдельном маленьком окне, тап мимо закрывает его.
- Сервис — `foregroundServiceType="specialUse|mediaProjection|microphone"`. На Android 14+ тип `mediaProjection`
  добавляется только после согласия пользователя (иначе система бросает исключение), до 14 — сразу.
  `microphone` добавляется, если есть разрешение. Он нужен, чтобы распознавание речи работало, пока Touchnotes
  на переднем плане.

## Снимок экрана

- Один виртуальный дисплей на сессию (Android 14+ не даёт создать второй), и **экран идёт в него всё время**,
  пока наставник включён; последний кадр держится открытым. Раньше приёмник кадров подключался только на время
  снимка ради батареи, но на реальном планшете это сломалось: на неподвижном экране система после подключения
  кадр не присылала, и снимок не получался никогда («экран не прислал кадр»). Фоновое слежение за конспектом
  снимало экран каждые 2 с и усугубляло это: попытки ждали впустую и держали захват. Кадры приходят только при
  изменениях экрана, поэтому на неподвижном листе батарея не тратится.
- Снимок для вопроса берёт кадр, пришедший позже, чем спрятались наши окна. Нет такого (экран неподвижен) —
  невидимая точка 1×1 в углу (под строкой состояния) чуть меняет цвет, и система рисует свежий кадр. Нет и
  его — берётся последний кадр: на неподвижном экране он и есть текущий. Фоновое слежение просто берёт
  последний кадр, не ожидая.
- Если снимок всё же не удался дважды подряд, разрешение на снимок экрана сбрасывается: при следующем нажатии
  Android спросит его заново.
- На Android 14+ системный диалог вызывается с `createConfigForDefaultDisplay()`: сразу «весь экран»,
  без режима одного приложения.
- Экран-объяснение «Разреши снимок экрана» показывается при первом запросе. Дальше сразу открывается системный
  диалог: на Android 14+ его приходится подтверждать в каждой новой сессии, и лишний экран раздражал бы.
  На время диалога кнопка, меню и заметки убираются, чтобы его не заслонять.
- Перед снимком все наши окна (кнопка, меню, рамки, заметки) получают `alpha = 0`, затем пауза 180 мс, чтобы система перерисовала экран.
- Строка состояния и навигация обрезаются по **видимым сейчас** системным панелям (Android 11+): если Touchnotes
  в полноэкранном режиме, ничего лишнего не отрезается. На Android 10 берутся стандартные размеры панелей.
- В режиме «Выделить область» сначала делается полный снимок, затем он показывается под затемнением, и область
  обводится прямо на нём. Так координаты точно совпадают с пикселями, а затемнение не попадает на снимок.
  Режим включается в меню долгого нажатия на кнопку, есть кнопки «Весь экран» и «Отмена».
- Длинная сторона до 1500 px, JPEG 85%, только уменьшение.

## Дизайн «чернила и бумага» (заменён «жидким стеклом», см. выше; полная переработка по просьбе «сделай сам, современно и красиво»)

- Прежние стили (радуга Google, Gemini) больше не используются. Идея: приложение — тихий помощник рядом с
  тетрадью. Тёплый «бумажный» фон `#F4F2EE`, графитовый текст `#16161A`, один яркий фиолетово-синий акцент
  `#5B4CF0` (с градиентом в `#8E5CF7`), спокойные цвета видов заметок: ошибка — коралловый `#E5484D`,
  следующий шаг — акцент, верно — зелёный `#1F9D60`, теория — янтарный `#D9822B`.
- Приложение всегда светлое, даже при тёмной теме системы: заметки поверх Touchnotes, предпросмотр чистовика
  и PDF — это бумага, и тёмные экраны между ними выглядели бы чужими (а графитовые кнопки терялись на тёмном фоне).
  Значки строки состояния при этом всегда тёмные.
- Шрифт **Onest** (OFL 1.1, сделан под кириллицу; взят из пакета Google Fonts, лицензия — `assets/fonts/OFL.txt`):
  в приложении (Compose), в окнах поверх Touchnotes, в тексте заметок, в истории и в заголовках чистовика.
  Крупная типографика: заголовок главного экрана 34 sp, плотный трекинг.
- Вместо рамок — мягкие тени, скругления 14–28 dp. Свои компоненты: карточки с тенью, кнопки-пилюли
  (графитовая главная, светлая второстепенная), сегментный переключатель с белой «таблеткой», своё «радио».
- Главный экран: значок и название, крупный заголовок «Решай сам. Я подскажу, где нужно.», тёмная карточка
  состояния с фиолетовым свечением и главной кнопкой, чипы готовности, плитки, шаги «Как это работает».
- Первая настройка — полоски прогресса и одна карточка шага по центру; история — карточки и переключатель
  «Задачи / Чистовики».
- Поверх Touchnotes: кнопка — графитовый круг с тонким фирменным кольцом и белой искрой, пока наставник думает,
  по кольцу бежит светлая дуга. Меню и сообщения у кнопки — тёмные карточки (хорошо видны на белом листе),
  главная кнопка в них — белая. Заметка — белая карточка с мягкой тенью, метка вида — цветная «пилюля»
  («Ошибка», «Следующий шаг», «Верно», «Теория»), главная кнопка — графитовая. Подсветка строки — лёгкий маркер.
- Иконка приложения — белая искра на фиолетово-синем градиенте.
- Сначала дизайн собран и проверен в HTML-макетах (Playwright), потом перенесён в приложение.

## Жёсткая самопроверка: единый стиль и мелкие ошибки

- **Все значки одного цвета — графитовые**, в одинаковых стеклянных квадратах: плитки главного экрана, история,
  прогресс, чистовик, повторение, оба меню у кнопки (короткое и по долгому нажатию — теперь у него тоже значки).
  Раньше они были вперемешку: графит, оранжевый, серый, зелёный. Параметра цвета у значка больше нет, чтобы
  разнобой не вернулся. Цвет остался только у смысла: красный — ошибка, зелёный — верно (и точки «всё в
  порядке»), янтарный — теория; у заметок на записи — метка вида и подсветка строки.
- Огонёк серии в «Прогрессе» тоже графитовый; пустые части полосок и ползунков — полупрозрачный графит
  (серые на стекле почти не были видны); ползунки в настройках — свои, графитовые.
- **Главный экран всегда знает, включён ли наставник**: раньше он мог показывать «Сейчас выключен», если
  кнопку включили плиткой в шторке, ярлыком или выключили из уведомления. Теперь экран подписан на состояние.
- В нижней строке страниц PDF тема без LaTeX (`x³`, `x₁`, `→`), как в названии файла.
- Выбор области: панель кнопок и подсказка больше не залезают под панель навигации и строку состояния.
- Меню по долгому нажатию не уходит за нижний край, если кнопка стоит низко.
- Строка «Спросить…»: клавиатура показывает «Отправить», а не перенос строки; длинный вопрос переносится по словам.
- Карточка повторения: вопрос и ответ по центру, а не прижаты к верху с пустотой снизу.
- Окно «Разреши снимок экрана» — белое: полупрозрачное стекло поверх затемнения выглядело серым.
- Значки шагов первой настройки по смыслу: слои — «поверх окон», колокольчик — уведомления, картинка — снимок.
- Значок уведомлений — искра наставника (как у плитки и напоминаний), а не лампочка.
- Убраны остатки старых дизайнов и мёртвый код: фиолетовый в схеме цветов, неиспользуемые цвета и фоны кнопок,
  варианты кнопок «для тёмной карточки», шесть неиспользуемых функций, 50+ лишних импортов.

## «Жидкое стекло», короткие подсказки и весь конспект (по просьбе: «вместо акцентного цвета — прозрачная плашка, плашки ничего не закрывают, агент видит весь конспект, коротко + подробнее»)

**Дизайн.** Фиолетово-синий акцент убран совсем. Выделение теперь делают стекло и контраст:
- Поверх Touchnotes всё — «жидкое стекло»: полупрозрачная светлая пластина (сверху плотнее — блик, книзу
  прозрачнее), светлая кромка и тонкая тёмная линия по краю, чтобы стекло читалось и на белом листе.
  Это кнопка (стеклянный круг с графитовой искрой; пока думает — по кромке бежит графитовая дуга), меню,
  сообщения, строка вопроса, выбор области и заметки. Настоящего размытия под окном Android поверх чужих
  приложений не даёт (`FLAG_BLUR_BEHIND` размывает прямоугольник окна целиком, с углами и тенью, и на многих
  планшетах выключен), поэтому стекло «матовое» за счёт плотности: текст читается, записи под ним видны.
- В приложении — бумажный фон с тремя очень мягкими цветными пятнами (холодное, тёплое, мятное): без них
  прозрачная пластина на ровном фоне не читается как стекло. Карточки, плитки, переключатели и кнопки —
  стеклянные; главная кнопка — графитовая. Цвет остался только там, где он что-то значит: красный — ошибка,
  зелёный — верно, янтарный — теория. Подсказка «следующий шаг» — графитовая.
- Иконка — графитовая искра на светлом «стекле»; в чистовике и истории фиолетовый тоже заменён графитом.

**Заметки ничего не закрывают.**
- Модель пишет каждую заметку из двух частей: короткая подсказка (одна фраза до 12 слов), затем строка
  `@@ подробнее` и полная подсказка (до 80 слов, теория — до 150). Приложение показывает только короткую.
  Если модель забыла короткую часть, короткой становится первая фраза полной (точки внутри формул не считаются).
- Свёрнутая заметка узкая (300 dp) и низкая; «Подробнее» расширяет её до 420 dp и показывает полную
  подсказку, «Коротко» сворачивает. Кнопки «Понятно» больше нет — закрывает крестик; кнопки меньше.
- Стекло заметки полупрозрачное (непрозрачность 84 % вверху и 70 % внизу), и место для неё по-прежнему
  ищется там, где на листе нет записей.

**Весь конспект.** Наставник раньше видел только один экран — теперь видит конспект целиком:
- Страница, на которой студент спросил, запоминается. После этого приложение (раз в 2 с, по уменьшенному
  кадру, который никуда не уходит) следит, как студент листает *ту же* тетрадь: пока страница едет, копит
  сдвиг; когда остановилась и на экране больше 40 % нового — делает снимок и запоминает страницу с её
  местом в тетради. Свои окна на снимке закрашиваются цветом листа.
- Если на экране всё сменилось и это не знакомая страница (другое приложение, перелистнули), приложение
  перестаёт запоминать — без спроса чужие экраны в конспект не попадают. Вернулся на знакомую страницу или
  спросил снова — продолжает. «Пролистать весь конспект» (долгое нажатие) запоминает и после перелистывания.
- К вопросу прикладываются до 8 других страниц (к тихой проверке — до 4) в порядке тетради, а не съёмки;
  если страниц больше — ближайшие к текущей. Они уходят в уменьшенном виде (до 0,55 Мп), текущий экран —
  последним, с номерами строк. Модель знает: условие, определения и прошлые шаги могут быть на других
  страницах, а отмечать места можно только на последнем снимке.
- Страницы хранятся в папке приложения (до 16, 12 часов), переживают перезапуск; «Забыть конспект» стирает
  их, «Только экран» в настройках выключает всё это. Чистовик может собраться из всех страниц («Весь конспект
  (N)»); снимков в чистовике теперь до 8, модель склеивает повторы.

## Учебный цикл: похожая задача, карточки, прогресс (по просьбе «выжми максимум, придумай сам»)

Наставник помогал решить одну задачу, но знания так не закрепляются. Добавил то, что делает из него учебный продукт:
**решай → закрепи → повторяй → видь прогресс**. Всё работает на планшете, без новых серверов.
- **«Похожая задача».** После верного решения в заметке вместо «Понятно» стоит «Похожая задача» (рядом
  «Сделать чистовик»), и тот же пункт есть в меню кнопки. Наставник придумывает задачу на тот же метод с
  другими числами и не решает её — правило «не решать за студента» сохраняется.
- **Карточки.** Модель чистовика вместе с конспектом возвращает 4–8 карточек `{"q","a"}` — только то, что есть
  в записях (определения, теоремы, формулы, шаги метода). Приложение берёт не больше 12, без пустых и повторов.
  Отдельного запроса к нейросети нет — карточки приходят в том же ответе.
- **Интервалы — коробки Лейтнера**, а не SM-2: две кнопки «Помню / Не помню» понятнее четырёх оценок, а для
  конспектов первого курса точности хватает. Интервалы 1, 3, 7, 16, 35 дней. Срок «на завтра» наступает в
  4 утра, а не ровно через сутки, чтобы вечерняя карточка была доступна утром. Забытая карточка уходит в
  первую коробку и показывается ещё раз в конце той же тренировки.
- Карточки и формулы рисует тот же движок, что заметки (Markdown + KaTeX в WebView); высота подстраивается
  под текст.
- **Прогресс.** Каждое учебное событие — вопрос наставнику, найденная тихой проверкой ошибка, чистовик,
  повторённая карточка — пишется в таблицу `activity`. Отсюда серия дней подряд по местному календарю
  (сегодня ещё не занимался — серия не сгорает до полуночи), лучшая серия, столбики за 14 дней и «Где чаще
  ошибаешься»: темы задач, где наставник находил ошибки (и где забывались карточки) за 30 дней. Тема задачи —
  её название из `@@ тема`.
- График — один ряд столбиков одного цвета без легенды; выбранный день ярче, касание столбика показывает
  число. Пустой день — тонкая серая чёрточка, чтобы было видно, что это ноль, а не пропуск.
- **База v1 → v2 с миграцией**: история задач и чистовики при обновлении сохраняются (тест на эмуляторе
  откатывает базу к v1 и проверяет, что Room принимает миграцию).
- **Напоминание** — неточный будильник `AlarmManager` (без разрешения на точные будильники и без WorkManager):
  раз в день, по умолчанию в 18:00, только если есть карточки к повторению и сегодня занятий не было.
  После перезагрузки планшета будильник ставится заново.
- **Плитка в шторке** включает и выключает наставника. Кнопка поверх Touchnotes — это foreground-сервис, а
  Android 14 разрешает запускать его только из видимого окна, поэтому плитка открывает невидимое окно на долю
  секунды. **Ярлыки** на значке: «Запустить» (включает и сразу уходит к Touchnotes), «Повторение», «Прогресс».
- Главный экран: блок «Сегодня» (сколько карточек ждёт и одна кнопка «Повторить»), плитки «Повторение»,
  «Прогресс», «История», «Чистовик»; «Как это работает» описывает весь цикл. Настройки — значок вверху.

## Доводка до готового продукта (самопроверка)

Прошёл всё приложение целиком, как студент, и исправил то, что мешало:
- **Тихая проверка больше не «съедает» нажатие.** Раньше, если фоновая проверка шла в момент нажатия
  «Подсказка», вопрос молча игнорировался. Теперь вопрос студента важнее: проверка останавливается и уступает.
  Остановленный запрос больше не может стереть с экрана новый ответ.
- **Ошибка — кнопка «Повторить».** Сеть моргнула или сервис перегружен — тот же вопрос задаётся одним нажатием.
  Если виноваты настройки (ключ, баланс, модель) — по-прежнему кнопка «Настройки».
- **Ответ «всё верно» без заметки** на вопрос студента показывается зелёной заметкой, а не пустотой.
- **Сбои не роняют наставника.** Неожиданная ошибка при снимке, слежении за страницей или сборке чистовика
  превращается в понятное сообщение, а не в закрытие приложения.
- **Ключ сохраняется сразу при вводе** — раньше он терялся, если уйти с экрана, не нажав «Сохранить».
  Под полем видно «Сохранён · …последние 4 символа», «Проверить ключ» показывает итог зелёной или красной строкой.
- **Названия задач в истории.** Наставник первой строкой ответа пишет тему (`@@ тема Экстремумы функции`);
  студент её не видит, а задача в истории получает это имя вместо «Задача · 27 октября, 22:16».
  История сгруппирована по дням («Сегодня», «Вчера», «12 октября»), удаление — с подтверждением.
- **Чистовик — отдельный понятный экран.** Плитка «Чистовик» на главном открывает его: если чистовика нет —
  объяснение в три шага и «Посмотреть пример» (встроенный конспект без нейросети, бывший «Тест чистовика»).
  Все кнопки — в общем стиле. Чистовик, открытый кнопкой поверх Touchnotes, по «Назад» возвращает в Touchnotes;
  открытый с главного экрана — на главный.
- **Названия чистовиков без LaTeX-мусора:** `x^3` → `x³`, `x_1` → `x₁`, `\to` → `→`, `\infty` → `∞`.
- Настройки нейросети, история и чистовик переведены на общие компоненты (кнопки-пилюли, скруглённые поля,
  «таблетки» вариантов, строки итога); убраны последние стандартные кнопки Material и остатки «радуги Google».
- Что сознательно **не** добавлял: распознавание голоса без интернета, синхронизацию истории между
  устройствами и «режим экзамена» — без них приложение полное, а каждая такая функция — новые разрешения или
  серверы. Подписанная release-сборка тоже не нужна для установки на свой планшет: debug-APK ставится так же.

## Точное выделение и поведение заметки (по отзыву «выделяется криво», «окно исчезает»)

- **Номера строк вместо угадывания координат.** Модели плохо называют пиксели на рукописном снимке, зато
  отлично читают напечатанные цифры. Приложение само находит строки записей (`InkLines`): пиксели заметно
  темнее/светлее фона листа — «чернила»; линовка и клетка (линии через полстраницы и больше) отбрасываются;
  строки — полосы с чернилами, мелкие разрывы, индексы, степени и дробные черты приклеиваются к соседней строке;
  внутри строки ищутся куски через большие пропуски (несколько примеров в строке). Слева к снимку добавляется
  поле 44 px с синими номерами строк. Модель отвечает `@@ error стр 3`, `@@ ok стр 2-3`, `@@ hint после 5`;
  если ошибка только в части длинной строки — `стр 3 : рамка`, тогда берутся только куски строки внутри рамки.
- Рамка без номера («на глаз») притягивается к строкам, которые она задевает, и к чернилам внутри неё. Для
  подсказки «пиши здесь» рамка не притягивается: она указывает на пустое место.
- Снимок с полем по-прежнему не больше 1,15 Мп (поле учтено), координаты модели пересчитываются без поля.
- Для чистовика номера строк не рисуются.
- **Отметки как маркер:** полупрозрачная подсветка строки со скруглением; у ошибки — волнистое подчёркивание,
  у теории — полоса слева, у подсказки — пунктирное место. Значок вида — в кружке на углу.
- **Заметка не исчезает сама.** Раньше при «другой странице» она пряталась, а через 20 с удалялась; теперь
  прячется только подсветка строки. Заметка уходит только по «Понятно», крестику, «Убрать заметки» или новому
  вопросу. При прокрутке едет за записями, но всегда остаётся целиком на экране (если её прижало к краю
  и она отошла от строки — «хвостик» убирается). При повороте экрана подсветка прячется, заметка остаётся.
- **Перетаскивание** за заголовок с «ручкой» из точек — пальцем и **стилусом** (в остальной части заметки стилус
  по-прежнему делает её прозрачной и проходит насквозь). Перетащенная заметка «приколота»: при прокрутке не едет.
- Под последней заметкой кнопки «Ещё подсказка» (или «Сделать чистовик») и «Понятно».
- **Увеличение страницы.** Слежение по кадрам понимает только сдвиг. Если картинка изменилась не сдвигом
  (изменилось больше 4% клеток или «другой экран»), выделения прячутся, а когда два кадра подряд совпадут
  (жест закончился), делается свежий снимок без наших окон. На нём заново ищутся строки (`InkLines`), и
  отмеченная строка узнаётся по «почерку» (`LineMatch`): сколько чернил в каждом из 48 столбиков по её
  ширине — при изменении масштаба это почти не меняется. Похожие строки различают соседи сверху и снизу;
  ширина и высота строки должны меняться одинаково (масштаб один на страницу). Рамка переносится с тем же
  масштабом, так что часть строки остаётся частью. Сравнение всегда с исходным снимком ответа — ошибка не
  копится. Не узнали (другая страница) — выделение остаётся скрытым, повторная попытка — когда экран снова
  изменится. Для этого к ответу хранится яркость снимка записи (~1,2 Мп).
- **Глаз на заметке** прячет и показывает выделение этой заметки; заметка остаётся.

- **Выбор предмета убран**: предмет модель определяет сама и в подсказках, и в чистовике (папка в «Документах»).

## Ответ прямо на записи (без окна)

- По просьбе «не отдельное окно, а работать в фоне и выводить ответ там, где задание» панель удалена совсем.
  Остались кнопка, короткое меню рядом с ней (исчезает от касания мимо) и **ответ на самой записи**.
- **Формат ответа.** Модель начинает каждую заметку строкой `@@ <вид> <координаты>`: `error`, `hint` (где писать
  следующий шаг), `ok`, `theory`, `note` (без места). Это обычный текст, а не JSON, поэтому ответ по-прежнему
  печатается потоком: рамка появляется, как только пришла строка-метка, а текст заметки дописывается на глазах.
  Разбор терпимый: русские и английские названия, скобки и запятые, недописанная метка в потоке прячется,
  текст без меток становится одной заметкой без места.
- **Координаты по модели.** Claude получает в сообщении размер снимка и пишет пиксели этого снимка; чтобы API
  не уменьшил картинку сам и пиксели совпали, снимок теперь не больше **1,15 Мп** (и 1500 px по длинной стороне).
  Gemini обучен на `box_2d` — `[ymin, xmin, ymax, xmax]` в долях от 1000, так и просим. OpenAI-совместимые
  сервисы могут уменьшать картинку по-своему, поэтому для них доли от 1000 (x, y). Если модель прислала пиксели
  вместо долей, это распознаётся. Слишком тонкая рамка расширяется до видимой.
- Снимок — экран без системных панелей (или выделенная область), поэтому точка снимка однозначно переводится
  в точку экрана.
- **Окна.** Рамка — отдельное маленькое окно чуть больше самой рамки, `FLAG_NOT_TOUCHABLE`, непрозрачность 0,8
  (иначе Android 12+ не пропустит сквозь неё касания), в абсолютных координатах экрана (`fitInsetsTypes = 0`,
  вырез учитывается; после показа положение сверяется с `getLocationOnScreen`). Внутри рамки можно писать.
  Окно на весь экран не подошло: вместе с кнопкой оно давало бы суммарную непрозрачность больше 0,8, и
  система стала бы глотать штрихи.
- **Заметка** — окно с WebView (`note.html`: marked + KaTeX), шириной 380 dp (теория — 460 dp), высотой по
  тексту (до 45% экрана, дальше прокрутка). Место выбирает `CalloutPlacer`: справа, слева, снизу или сверху от
  рамки с разными выравниваниями; штраф за то, что заметка закрывает само место (самый большой), другие заметки
  и кнопку, за «чернила» под ней (по уменьшенному кадру экрана — пустое место листа лучше) и за расстояние.
  «Хвостик» карточки указывает на рамку.
- **Стилус рядом с заметкой** (наведение или касание) — заметка на 2,5 с становится прозрачной (по умолчанию 35%,
  настраивается) и не принимает касаний, штрих уходит в Touchnotes. Пальцем заметку можно перетащить за заголовок
  (хвостик тогда пропадает) или закрыть крестиком.
- **Слежение за страницей.** Пока ответ на экране, сервис раз в 2 с снимает кадр (без скрытия своих окон, чтобы
  ничего не мигало) и сравнивает его с кадром, по которому отвечал наставник. Кадры никуда не отправляются.
  Из кадра строятся две уменьшенные копии: серая сетка 160 клеток в ширину (честное усреднение) и «профиль
  строк» — средняя яркость каждой строки пикселей в 8 вертикальных полосах. Сетка отвечает на вопрос «та же
  страница или нет», профиль находит вертикальную прокрутку с точностью до пикселя. Первая версия искала сдвиг
  по сетке и на эмуляторе не узнала прокрутку на 379 px (не кратно клетке 16 px) — отсюда профиль.
  В профиле сравниваются только «информативные» строки (текст, края): однотонный фон совпадает при любом
  сдвиге и размывал оценку. Строка состояния и панель задач в сравнении не участвуют — они не двигаются
  со страницей; наши окна закрыты маской. Сдвиг по горизонтали (страницу увеличили) ищется по сетке.
  Итог: страница на месте — ничего не делаем; сдвинулась — рамки и заметки едут на этот сдвиг; на экране
  другое — прячем их, а через 20 с убираем. Сдвиг всегда считается от исходного кадра, ошибка не копится.
  На эмуляторе: страницу прокрутили на 379 px — рамка сдвинулась ровно на 379 px.
- **Фоновая проверка** («Следить за решением», по умолчанию выключена — каждая проверка платная). По тем же
  кадрам видно, что студент пишет. Когда он остановился на 5/10/20 с, уходит тихий запрос «проверь; если ошибок
  нет — ответь `[[ВЕРНО]]`». Ошибка — обычная рамка с заметкой; всё верно — кнопка мигает зелёным, а
  найденная раньше и уже исправленная ошибка убирается. Не чаще раза в 45 с; ответ на вопрос студента тихая
  проверка не перебивает; ошибка ключа или баланса ставит проверки на паузу до смены настроек. Тихие проверки
  в историю не пишутся. Зелёная точка на кнопке — проверка включена.
- **Разговор.** Каждый вопрос идёт со свежим снимком и историей текущей задачи (последние 12 реплик, без
  картинок). В историю ответ пишется текстом без координат («**Ошибка.** …»). Новая задача начинается сама,
  если наставника не спрашивали 40 минут (или из меню); «Продолжить эту задачу» в истории продолжает старую.
- **Вопрос своими словами** — строка ввода рядом с кнопкой (в верхней части экрана, чтобы её не закрыла
  клавиатура), с микрофоном. Распознанная речь подставляется, но не отправляется сама. Вопрос всегда идёт со
  снимком: без него не на что ставить рамку (настройка «прикладывать снимок» убрана).
- **Сообщения** (нет ключа, ошибка API, «Смотрю на экран…», сбор снимков для чистовика) — маленькая карточка у
  кнопки, а не окно.
- При повороте экрана рамки убираются: записи легли иначе.

## Чистовик

- Шаблон `assets/clean.html` + `clean.css` + `clean.js`: лист A4 = 794×1123 CSS px. Блоки раскладываются по листам
  на месте: блок, который не влез, переносится на следующий лист. Длинные решения и таблицы делятся по шагам
  и строкам («продолжение», шапка таблицы повторяется). Подзаголовок не остаётся один внизу листа. Слишком
  высокий одиночный блок уменьшается.
- Предпросмотр вписывается в ширину экрана предпросмотра. Ширину в CSS px передаёт приложение (`Clean.fit`) при каждой
  перекладке WebView: в окне поверх приложений `window.innerWidth` оказался ненадёжным, лист вылезал за край
  (видно на эмуляторе).
- Графики: SVG собственным кодом, выражения считает **math.js** (упакован в assets) в режиме `predictable`,
  поэтому `sqrt(-1)` даёт пропуск, а не комплексное число. Разрывы (асимптоты) не соединяются. Понимает и
  школьные записи `ln`, `tg`, `ctg`, `arcsin`.
- **PDF:** отдельный WebView шириной ровно в A4 временно встраивается в окно панели внутри контейнера 1×1 px
  (не виден, но честно сверстан). Каждый лист рисуется в Bitmap ≈200 dpi (1654×2339) и кладётся страницей
  в `PdfDocument`. PDF получается растровым: путь через `PrintDocumentAdapter` требует скрытых API.
  Зато PNG-страницы выходят из той же отрисовки бесплатно.
- Сохранение через MediaStore в `Documents/Конспекты/<Предмет>/<Тема> — <дата>.pdf`, PNG рядом
  («… — стр. N.png»). Если система не пустит картинку в «Документы», PNG уйдёт в `Pictures/Конспекты/<Предмет>`.
  Предмет для папки берётся из JSON чистовика: модель определяет его сама. LaTeX в имени файла упрощается
  (`$\frac{1}{x}$` → `1/x`).
- Рабочая копия файлов лежит во внутренней папке приложения. Её отдаём другим приложениям через `FileProvider`,
  и из неё «История» может переотправить чистовик.
- Отправка: среди приложений, принимающих PDF (`ACTION_SEND` и `ACTION_VIEW`), ищется то, у которого в пакете
  или названии есть «touchnotes». «Поделиться» предпочтительнее, чем «Открыть». В настройках: «Автоматически
  в Touchnotes» (по умолчанию), «Каждый раз спрашивать» или любое найденное приложение. Если выбранное
  приложение удалили, работает автопоиск.
- После сохранения панель сворачивается, чтобы не заслонять окно импорта Touchnotes. В панели остаются
  «Отправить ещё раз» и «Отправить картинками» (PNG, удобно вставлять в заметку).
- Многостраничный конспект: до 5 снимков, превью снимков, «Убрать последний».

## Данные

- Room: `conversations`, `messages`, `clean_notes`. Схема версии 1. При будущих изменениях схемы база
  пересоздаётся (`fallbackToDestructiveMigration`), для первой версии это допустимо.

## Большое расширение: 21 функция

### Любое приложение для записей
- Вместо жёсткой привязки к Touchnotes — список известных приложений по части имени пакета (Touchnotes,
  Samsung Notes, OneNote, Squid, Nebo, Xodo, Flexcil, Noteshelf, GoodNotes, Notewise, Kilonotes, Keep).
  Если в настройках ничего не выбрано, берётся первое установленное из списка; можно выбрать любое приложение
  с поиском. Чистовик отдаётся через обычный «Поделиться» в выбранное приложение — API у таких приложений нет.

### Тетрадь в приложении
- Свой движок рукописи, а не WebView/Canvas-библиотека: координаты страницы фиксированы (ширина 1000, A4 — 1414),
  штрих хранится как точки x, y, нажим; контур переменной ширины строится из нажима (0,35–1,5 от базовой),
  маркер рисуется с MULTIPLY, чтобы не закрашивать текст. Формат файла — свой бинарный (`NKI1`), страница в
  отдельном файле: сохранение одной страницы не переписывает всю тетрадь.
- Перо: `requestUnbufferedDispatch` (API 30+) и исторические точки MotionEvent — без «хвоста» за пером.
  Палец листает и масштабирует; если первым коснулась ладонь, а потом перо — пишет перо. Ластик — по
  `TOOL_TYPE_ERASER` или кнопке стилуса, стирает штрих целиком (так «Назад» прост и надёжен).
- Наставник в тетради видит не скриншот, а точный рендер страницы (без интерфейса) плюс соседние страницы
  поменьше. Метки рисуются на самом листе с номерами, а текст — в боковой панели (на узком экране — снизу),
  поэтому записи никогда не закрываются. Ответы в тетради — отдельный разговор, без 40-минутного таймаута.
- Фото — через ImageDecoder с уменьшением до 2400 px; PDF — PdfRenderer, ширина 1600 px, до 40 страниц.
  Фото и PDF присылают через «Поделиться»/«Открыть с помощью» — сразу новая тетрадь.

### Наставник умнее
- «Проверь ответ» и «Покажи шаг» — быстрые действия; «Сдаюсь» реализован как «Покажи шаг»: один следующий шаг
  с объяснением, а не всё решение.
- Память ошибок: после ответа отметки-ошибки (до 30, в промт уходят последние 8) сохраняются в настройках и
  добавляются в системный промт — наставник заранее предупреждает о типичных для студента промахах.
- Контрольная в тетради: таймер, подсказки скрыты, по «Сдать работу» — проверка всей работы с оценкой.
- Озвучка: системный TextToSpeech ru-RU, формулы перед чтением переводятся в слова («x в квадрате»).
- Вопрос голосом из меню кнопки сразу слушает и отправляет, без строки ввода.

### Тренировка
- Вариант, мини-тест и карточка из подсказки — обычные (не потоковые) запросы с ответом в JSON; парсер
  терпимый (вырезает от первой скобки до последней, выкидывает неполные задачи); при сбое — один повтор.
- Задачи варианта хранятся в `notebook.json` тетради; ответы видит только наставник — они добавляются
  в системный промт с правилом «не называй ответ, пока студент не решит или не попросит».
- Мини-тест: формулы рисуются KaTeX только там, где они есть, остальное — обычным текстом (десяток WebView
  на экране тормозил бы).
- Экзамены: дата хранится в настройках; при ответе на карточку срок следующего повтора ограничивается утром
  накануне экзамена по этому предмету (сравнение предмета без регистра и по вхождению).

### Конспекты
- Шпаргалка собирается без нейросети: из чистовиков берутся блоки «определение», «теорема», «формула»,
  повторы убираются, группировка по предметам и темам; результат открывается в обычном предпросмотре чистовика
  и сохраняется в PDF.
- Экспорт: Markdown (формулы `$…$`, блоки — цитатами), LaTeX (определения/теоремы — окружениями amsthm,
  спецсимволы текста экранируются, формулы не трогаются), Word — минимальный .docx, собранный вручную (без
  тяжёлых библиотек), формулы — курсивом Cambria Math с упрощением LaTeX (\frac → (a)/(b), греческие буквы).
- Поиск — по всем словам запроса, без учёта регистра и «ё», с весом совпадений в заголовке; служебная разметка
  ответов наставника (`@@ …`, `[[ГОТОВО]]`) из выдачи убирается.

### Удобство
- Расходы: каждый клиент оборачивается в `MeteredBackend`. Для Claude токены точные (из `message_start` /
  `message_delta` и `usage` обычного ответа), для остальных — оценка: 3 символа на токен, снимок — ширина×высота/750.
  Цены Claude — официальные ($2/$10 Sonnet 5.5, $0.10/$0.50 Haiku 5.5, $4/$20 Opus 5.5 за миллион), для других —
  ориентир. Лимит — в долларах за день; при превышении запрос не отправляется, а у кнопки понятное сообщение.
- Резервная копия: zip с базой (перед этим WAL сбрасывается в файл), тетрадями, PDF чистовиков и `settings.xml`.
  Зашифрованное хранилище с ключами в копию **не попадает никогда**. При восстановлении пути проверяются
  (никаких `../`), после — перезапуск приложения через AlarmManager.
- Виджет — RemoteViews со стеклянной пластиной: карточки на сегодня, серия, ближайший экзамен и три кнопки.
  Обновляется раз в час, после каждого повтора и при открытии приложения.
- Тёмная тема — «графитовое стекло»: цвета `Brand` читают состояние темы, поэтому все экраны перекрашиваются
  без перезапуска. Лист тетради, чистовик и заметки поверх других приложений остаются светлыми — это бумага.
  По умолчанию — светлая (как раньше), выбор — в настройках.
- Обновление из приложения: CI на каждый push публикует релиз `build-<номер>` с APK, `versionCode` = номер
  сборки GitHub Actions. Приложение спрашивает `releases/latest`, принимает APK только из этого репозитория,
  качает и открывает системный установщик. Подпись общая (debug-ключ в репозитории), поэтому ставится поверх.

### Редактор: отрисовка, жесты, анимации, тема, скорость
- Штрих раньше рисовался одним многоугольником-контуром после сглаживания (1-2-1). Сглаживание «съедало»
  мелкие детали букв, на разворотах пера контур перекручивался и давал щели, а последние точки при отрыве
  пера (они приходят вместе с ACTION_UP) терялись — отсюда обрезанные хвосты. Теперь штрих — плавная кривая
  через середины отрезков (концы не сдвигаются), нарисованная отрезками с круглыми концами, сгруппированными
  по толщине (Canvas.drawLines): без щелей при любых разворотах и быстро на GPU. Маркер — одной обводкой
  постоянной толщины, чтобы перекрытия не темнели. Точки отрыва пера добавляются в штрих.
- Готовая страница хранится картинкой размером с экран; при письме дорисовывается только новый штрих, при
  стирании и смене бумаги страница перерисовывается. Пока лист двигают, рисуем напрямую (без картинки).
- Жесты: лист едет по инерции (OverScroller), двойное касание пальцем — ×2.2 в точке касания или обратно по
  ширине, касание двумя пальцами — «Отменить» (как в популярных приложениях для конспектов), плавные переходы
  масштаба, курсор пера/ластика при наведении стилуса.
- Анимации: листание страниц (новая въезжает и проявляется), отметки наставника проявляются, панель
  выезжает, заметки въезжают снизу, выбранный цвет «вырастает» с пружинкой, палитра полупрозрачна, пока пишешь,
  «Думаю…» с дышащими точками и секундами.
- Тема не применялась: экран следил за потоком настроек, а тема в объект настроек не входила — новый объект
  был «равен» старому, и Compose не перерисовывал. Тема добавлена в настройки. В тёмной теме и сам лист тёмный:
  тёмная бумага и разлиновка, тёмные чернила рисуются светлыми, маркер — режимом SCREEN. В файле цвета не
  меняются, снимки для наставника, превью и чистовик всегда светлые.
- Скорость ответа: по умолчанию «Быстро» — усилие low; размышления выключены, где модель это позволяет
  (Sonnet 5.5 — `between_tools`, Haiku 5.5 — `disabled`; у Opus 5.5 выключить нельзя), у Gemini бюджет мыслей
  0 (Pro — 128), у GPT-5/o — reasoning_effort low; в запрос уходит меньше соседних страниц. Если сервис или прокси
  не понял параметры (ошибка 400), тот же вопрос сразу повторяется обычным запросом. «Вдумчиво» — как раньше.
  WebView для формул прогревается при открытии тетради, чтобы первая подсказка не ждала его запуска.

### Инструменты редактора и понятность
- Набор инструментов — как у привычных приложений для рукописных конспектов, но своими средствами:
  ручка, маркер, ластик (целиком / часть линии), лассо, фигуры, текст. Выбранный инструмент отмечает
  «пилюля», которая перетекает к нему с пружинкой; над рядом — только настройки этого инструмента.
  Подписи и подсказки по-русски; при первом открытии — короткая карточка с жестами.
- Задержка пера на месте 0,9 с — временный ластик (виброотклик, круг ластика «распускается»); как только
  перо сдвинулось от места касания больше чем на 5 dp, это письмо, и ластик не включится. Отпустил — снова ручка.
- Нарисовал и задержал перо 0,55 с — распознавание: прямая (все точки ближе 6 % длины к отрезку; почти
  горизонтальная/вертикальная/45° выравнивается), замкнутая фигура упрощается (Рамер — Дуглас — Пекер):
  3 угла — треугольник, 4 угла с почти прямыми углами — прямоугольник, иначе — овал, если точки близко к
  эллипсу в рамке. Каракуля плавно «перетекает» в фигуру. Фигуры — штрихи с видом SHAPE: без сглаживания
  и нажима, поэтому углы острые.
- Лассо выделяет штрихи, у которых внутри больше половины точек, и тексты, у которых внутри середина.
  Пока выделено, это не рисуется в картинку страницы, а рисуется поверх с ореолом — перетаскивание идёт без
  задержек. Все сложные правки (лассо, частичный ластик, текст, цвет, очистка) — один шаг «Отменить».
- Печатный текст хранится в странице (формат NKI2; страницы NKI1 читаются как раньше).
- Панель наставника: два состояния. «Ответ» — только ответ на всю панель; «Вопросы» — плитки с подписями,
  свой вопрос, проверка «когда остановлюсь»; последний ответ — одним касанием.
- Анимации: перетекание инструмента, смена настроек, листание с уходом и уменьшением старой страницы,
  тающее стёртое, бегущая рамка выделения, пружинящее меню выделения, морфинг фигуры, нажатие плиток.

### Оформление и свои темы
- Лист тетради всегда белый, как бумага, в любой теме: от темы зависит только «стол» вокруг листа.
  Чернила, разлиновка, выделение и курсор рисуются как на бумаге. Снимки для наставника — те же.
- Свои темы вместо одной светлой и одной тёмной: 6 светлых (Бумага, Океан, Мята, Закат, Лаванда, Сакура)
  и 4 тёмные (Графит, Полночь, Лес, Эспрессо). У каждой — фон, три пятна под стеклом, текст, акцент, стекло.
  «Бумага» и «Графит» повторяют прежний вид. Режим: как в системе / светлая / тёмная; при «как в системе»
  днём берётся выбранная светлая, ночью — выбранная тёмная.
- Акцент (кнопки, выбранное, переключатели, индикаторы) — по теме или свой из 10 цветов; цвет текста на
  акценте подбирается по яркости. Фон: пятна, «живые» пятна (медленно плывут, меняется только рисование),
  градиент, ровный. Размер текста: мельче / обычный / крупнее.
- Смена темы — цвета плавно перетекают за полсекунды; экраны сменяются с проявлением и лёгким масштабом;
  кнопки «проседают» под пальцем с пружинкой, у акцентных — мягкая цветная тень и блик сверху.

### Плашка инструментов и меньше лишнего
- Инструменты — узкая вертикальная плашка у края листа (по умолчанию слева). Под инструментами — кружок
  с цветом и толщиной (у фигур — вид фигуры, у ластика — «1» или «½», у текста — цвет). Цвета, толщина и
  остальные настройки открываются во всплывающем окне по касанию кружка или выбранного инструмента ещё раз
  и закрываются касанием мимо или выбором цвета. Плашку можно перетащить за ручку вверх-вниз и к другому краю —
  положение запоминается. Пока пишешь, она почти прозрачная.
- Убрано лишнее: кнопка «+» в тетради (всё — в одном меню «…»), «Контрольная» и «Проверять, когда
  остановлюсь» переехали в это меню, в панели наставника — только шесть вопросов и свой вопрос; на главном —
  без кнопки оформления и ссылки «Как это работает»; в настройках редко нужное свёрнуто в «Дополнительно».

## Суперприложение: телефон + планшет, расписание, карта, напоминания, синхронизация
(по просьбе: «на планшете пишу, на телефоне решаю карточки и делаю напоминалки; интеграция с Lecturial-2;
карту универа оптимизируй; различай устройство; синхронизируй всё»)

### Телефон и планшет
- Режим определяется по наименьшей ширине экрана (600 dp и больше — планшет), но его можно выбрать вручную в
  «Настройки → Это устройство» (Сам / Телефон / Планшет) — например, для складного телефона.
- **Телефон** — четыре вкладки внизу: «Сегодня» (идущая и следующая пара, напоминания, карточки и серия),
  «Расписание», «Карта», «Учёба» (повторение, прогресс, напоминания, конспекты с планшета, чистовики).
  Тетрадей для стилуса, наставника поверх записей, тренировок с нейросетью и настроек нейросети на телефоне нет.
  Тетради с планшета открываются **только для просмотра** (страницы одна под другой, двумя пальцами — приблизить).
- **Планшет** — как раньше, плюс на главном «Пары сегодня» и в списке разделов «Расписание», «Карта кампуса»,
  «Напоминания».
- Вкладки сменяются с проявлением и сдвигом в сторону перехода; подсветка вкладки переезжает с пружинкой,
  значок «подпрыгивает».

### Расписание (интеграция с Lecturial 2)
- Взял из Lecturial 2 (Apache 2.0) то, ради чего он ценен, — загрузку с schedule.siriusuniversity.ru: сайт на
  Livewire, поэтому клиент открывает страницу, берёт начальное состояние и CSRF-токен и «нажимает» те же кнопки,
  что браузер (выбор группы, следующая неделя). Перенёс в `schedule/SiriusClient.kt` с указанием авторства,
  переписал на kotlinx.serialization (без org.json) и OkHttp 4, оставил только группы (режим преподавателя и
  аудиторий студенту не нужен). Тесты на мок-сервере — по мотивам тестов Lecturial.
- Сам Lecturial как отдельное приложение не встраивал: у него свой Room, Material You, виджет, Outlook и Google
  Календарь — это второе приложение в приложении. «Единое приложение» = расписание в нашем стиле и связано с
  остальным: аудитория пары → маршрут по карте, «скоро пара» → уведомление с маршрутом.
- Кеш — файлы недель (`files/schedule/<хеш группы>/<понедельник>.json`): без сети показываем последнее, с сайта
  обновляем не чаще раза в 3 часа (или кнопкой). Группа и преподаватель иностранного синхронизируются между
  устройствами; сами недели — нет (каждое устройство скачивает их само, так свежее).
- Уведомление «скоро пара» — за 5/10/15 минут (по умолчанию 10), точный будильник на ближайшую пару; нажатие
  открывает карту с аудиторией.

### Карта кампуса (из присланного APK навигатора ГМЦ)
- В APK — 63 МБ ассетов: план ГМЦ (3 этажа) и пансиона на Рекордов, 15 (7 уровней), сетки проходимости 0,3 м,
  Wi-Fi-отпечатки для определения места, 15 МБ записей прогулок для отладки (replay), голосовые фразы из
  автомобильного навигатора («камера», «скорость 60»…).
- Код навигатора я не декомпилировал (запуск декомпилятора здесь запрещён) — разобрал **форматы данных**
  (они самоописывающие: JSON-заголовок + массивы) и написал карту заново, в стиле приложения.
- `tools/campus/build_campus.py` пересобирает данные: координаты — int16 с шагом 2,5 см вместо float32, стены —
  индексированные треугольники, сетки — построчные серии вместо 11 МБ на этаж, отпечатки — двоичный файл;
  отброшены записи прогулок, голосовые фразы и отладочные правки. **63 МБ → 4,3 МБ** (в APK ~2,4 МБ).
  Голосовые подсказки не взял: это фразы для машины, и у них непонятные права.
- Отрисовка: помещения и стены — `drawVertices` (треугольники, пачками до 30 000 вершин), двери, лестницы,
  мебель (при приближении), ограды и дорожки — линиями; подписи — без наложений, крупные помещения раньше мелких.
- Маршрут: A* по сетке, 8 соседей, без срезания углов; помещения «по ключу» в 6 раз «дороже» — путь идёт через
  них, только если иначе никак. Поиск в окне вокруг начала и конца (вся сетка ГМЦ — 5,8 млн клеток, окно —
  в разы меньше; если в окне не нашлось — по всей сетке). Между этажами — через лестницу, лифт или эскалатор,
  общий для обоих этажей, с наименьшей суммой: путь до него + путь от него + «цена» перехода (лестница — 40 м
  на этаж, лифт — 60 м ожидания + 8 м на этаж). Ломаная спрямляется по прямой видимости. Около 0,1 с на этаже,
  0,6 с между этажами (на JVM).
- «Откуда»: по умолчанию — аудитория предыдущей пары сегодня; можно «Я здесь» (Wi-Fi) или коснуться помещения.
- «Где я» — см. раздел «Определение места» ниже.
- Аудитории из расписания находятся по названию корпуса («Альфа 5.8» — но не «Альфа 5.10» для «Альфа 5.1»),
  по коду («1-07-18») и К-аудиториям («К_У. К4» → «К4»). Сайт иногда пишет название дважды («Альфа 5.8Альфа 5.8») —
  это учтено.
- Анимации: камера плавно летит к аудитории и к маршруту (масштаб — по логарифму), новый этаж проявляется,
  маршрут «вытягивается» от начала к концу, по нему бегут точки, булавка «дышит», «я здесь» пульсирует,
  переключатель этажей — скользящая подложка.

### Напоминания
- Свои напоминания: название, заметка, время, повтор (один раз / каждый день / по будням / раз в неделю).
  Быстрые варианты «Через час», «Сегодня в 20:00», «Завтра в 9:00», плюс календарь и часы.
- Точные будильники (`USE_EXACT_ALARM`: приложение распространяется не через Play, а это и есть напоминания).
  В уведомлении — «Готово». Повторяющееся после срабатывания переносится на следующий раз.
- Срабатывают на всех устройствах, где есть приложение: создал на планшете — телефон напомнит тоже.

### Синхронизация
- Своего сервера нет — синхронизация через облако, которое у студента уже есть: **Яндекс Диск** или любой
  WebDAV (Nextcloud, ownCloud…). Пароль и токен — в EncryptedSharedPreferences, в журнал не пишутся, как и ключ API.
- **Яндекс Диск — через REST API (cloud-api.yandex.net) по OAuth-токену, а не WebDAV.** С 22 июня 2026 Яндекс
  пускает по WebDAV только подписчиков Яндекс 360, бесплатным аккаунтам отвечает 402 Payment Required
  (так и случилось у пользователя). REST API на бесплатном Диске работает. Регистрировать своё OAuth-приложение
  не нужно: токен выдаёт Полигон Яндекса (yandex.ru/dev/disk/poligon) кнопкой «Получить OAuth-токен», он живёт
  около года. Загрузка и скачивание — через одноразовые ссылки, которые выдаёт API; папки — PUT /resources
  (409 — уже есть). Старое подключение по WebDAV остаётся рабочим для тех, у кого Яндекс 360; на 402 приложение
  подсказывает переподключиться по токену.
- Устройство пишет только свой файл `Nastavnik/devices/<id>.json.gz` — всё состояние, как оно его видит; файлы
  (страницы, подложки, PDF) — в `Nastavnik/blobs/<sha256>`, записываются один раз. Никто не перезаписывает
  чужое, поэтому блокировки не нужны, а слияние простое: по каждой записи — самая свежая версия; удаление — тоже
  версия (помним 90 дней). Файлы отправляются раньше снимка, чтобы ссылки не повисали.
- Что изменилось на устройстве, движок определяет сам — сравнивая с тем, что было после прошлой синхронизации.
  Остальной код не нужно переделывать под «отметь изменение». Цена: время правки = время синхронизации;
  при одновременной правке одной записи на двух устройствах побеждает последняя синхронизация. Для этой связки
  (пишут на планшете, повторяют на телефоне) конфликтов почти нет.
- Синхронизируются: тетради, карточки, учебные события (прогресс и серия), чистовики с PDF, напоминания,
  группа, преподаватель иностранного и экзамены. Не синхронизируются: разговоры с наставником (привязаны к
  устройству и ключу API), ключи API, оформление и расходы.
- У записей БД появились общие идентификаторы `uid` (миграция 2 → 3 выдаёт старым записям случайные).
  Тетради и так имеют уникальные номера (время создания).
- Когда: при открытии приложения (если не было 1,5 минуты), при уходе из него, через несколько секунд после
  повторения карточек, правки напоминаний и экзаменов, и кнопкой. Ошибки сети не мешают работе — всё локально.


### Определение места (по просьбе «максимально точно, тот же этаж и та же аудитория»)
- В APK навигатора нашлись **записи настоящих прогулок по ГМЦ**: акселерометр, ориентация, датчик шагов,
  барометр, сканы Wi-Fi и отметки истинного положения (каждые несколько секунд). На них я построил стенд и
  подбирал алгоритм по цифрам, а не «на глаз». Честная проверка: отпечатки этого же прохода (±60 с) убираются —
  как будто человек пришёл сюда в другой раз.
- Результаты на стенде (362 отметки, ГМЦ):

  | | этаж | помещение | медиана ошибки |
  |---|---|---|---|
  | было: k ближайших по одному скану | 73 % | 50 % | 17 м |
  | один скан, новая модель сигнала | 96 % | 72 % | 13 м |
  | **фильтр частиц (сейчас)** | **98–100 %** | **78–80 %** | 11–12 м |

  Ошибка в метрах упирается в покрытие: обходчик прошёл многие места один раз, и в проверке рядом с человеком
  нет отпечатка ближе ~7 м. Там, где ходили несколько раз, и после «Не здесь?» — точнее.
- Модель Wi-Fi: уровень сигнала ~ N(измеренный, 8 дБ) по 40 самым сильным точкам скана; точку, которой у
  отпечатка нет, штрафуем тем сильнее, чем она громче. Вес отпечатка — по **абсолютному** качеству совпадения:
  если похожих рядом нет, Wi-Fi почти не двигает оценку (иначе он тянул к «наименее плохому» и сбивал шаги —
  это дало +5 % по помещению).
- Фильтр частиц (800): шаг — датчик шагов (или свой детектор по акселерометру), курс — вектор поворота с
  магнитометром (на записях он совпал с настоящим направлением с поправкой 5–14°; у каждой частицы своя
  поправка и своя длина шага 0,6–1 м — их «находит» фильтр); частица, прошедшая сквозь стену, почти обнуляется;
  3 % частиц на каждом скане — заново из Wi-Fi, чтобы фильтр не «терялся».
- Этаж: голосование частиц; смена этажа — когда давление за 15 с изменилось больше чем на 0,45 гПа (≈ 4 м)
  и частица у лестницы или лифта. Давление «плывёт» (за 10 минут — до 9 гПа), поэтому только быстрые изменения.
- Место — центр самого плотного облака частиц (не среднее: при двух облаках среднее попадает в стену);
  помещение — голосованием частиц по сетке. GPS — только на территории (точность лучше 25 м), через привязку
  плана к широте/долготе из данных навигатора.
- Корпус выбирается сам — чьих точек доступа видно больше.
- **«Не здесь?»** — коснуться места на карте: оценка сразу переносится туда, а текущий скан сохраняется как свой
  отпечаток (`files/campus/<корпус>/my_wifi.json`, до 300). Так свои аудитории узнаются всё точнее. Свои
  отпечатки пока не синхронизируются: у телефона и планшета разные антенны.
- Слежение работает только пока открыта карта (батарея): Wi-Fi раз в 30 с (Android разрешает 4 скана за 2 минуты),
  между ними — шаги. Разрешения: местоположение (без него Android не отдаёт список сетей) и «физическая
  активность» (датчик шагов; без неё — шаги по акселерометру).
- Точка «я здесь» плавно доезжает до новой оценки, вокруг — круг точности, луч — куда смотришь; карта следует
  за тобой, пока сам её не сдвинешь.


## Маршрут по шагам, живые уведомления, движение и вид Android 16–17, успеваемость
(по просьбе: «маршрут поэтапно как в обычных картах, оптимизируй карту, много топорных анимаций,
ближе к дизайну Android 17, живые уведомления, успеваемость по паролю от ЛКС»)

### Навигация по шагам
- Маршрут превращается в манёвры (`campus/Navigation.kt`): «Иди прямо 10 м», «Поверни направо у „Бета 3.1“»,
  «Поднимись на 3 этаж» (лестница/лифт/эскалатор), «Ты на месте — слева». Угол меньше 50° — не поворот:
  иначе на дуговом коридоре ГМЦ было «держись правее» каждые 10 метров. Ориентир — ближайшее помещение
  с понятным названием в пределах 7 м; длинные названия сокращаются до номера.
- Экран навигации как в картах: сверху крупная плашка акцентного цвета со стрелкой манёвра, «через 15 м»,
  что сделать и где; под ней — «Затем» со следующей стрелкой. Снизу — сколько минут и метров, «Все шаги»,
  «Завершить». Карта подлетает к месту манёвра, этаж переключается сам.
- С «где я» шаги переключаются по мере движения (проекция места на линию маршрута); отошёл от маршрута дальше
  10 м (с поправкой на точность) три раза подряд — маршрут перестраивается от текущего места.

### Карта быстрее
- Подписи считаются один раз на этаж (текст, ширина, точка), в кадре — без новых объектов и без measureText;
  проверка наложения — по массиву чисел. Пульс выбранного помещения и «я здесь» перерисовывает карту 30 раз
  в секунду, а не 60.

### Движение (анимации)
- Общие правила Material 3 (`Motion` в Common.kt): появление — кривая «emphasized decelerate» за 0,3–0,4 с,
  уход — «accelerate» за 0,1–0,2 с; перемещения — пружина почти без отскока. Убраны «прыжки»: значки вкладок
  больше не подпрыгивают, булавка не качается, кнопки проседают на 3 %, а не на 5 %.
- Смена экранов и вкладок — «сквозное проявление» (fade through) Material 3; карточки появляются со сдвигом
  12 dp (было 28 dp и масштаб), каскад — по 30 мс.

### Вид как в Android 16–17 (Material 3 Expressive), текущий стиль сохранён
- Нижняя панель телефона во всю ширину, под значком выбранной вкладки — «таблетка», которая растягивается;
  подписи всегда видны.
- Списки разделов — «сгруппированные»: отдельные плашки с большими скруглениями снаружи и маленькими между
  соседями, как в настройках Android 16.
- Новая тема «Обои» (светлая и тёмная): цвета из обоев телефона, как у системных приложений (Android 12+).

### ЛКС Сириуса (lks.siriusuniversity.ru)
- Сайт ЛКС пускает только с российских IP («временно ограничен доступ … из-за рубежа»): ни среда разработки,

  загружает сама: `POST /journal/get` с заголовком `X-CSRF-TOKEN` (из `<meta name="csrf-token">` страницы

  `lessons[]` (`title`, `avg_mark`, `rating`, `count_absent`, `items{дата: [{marks[{mark_value_standard,
  color, second_mark}], absent, absent_valid, comment, hometask}]}`) и `cacheBuilding` (пока сайт собирает
  журнал — повторяем через 3 с, как и страница).
- **На входе в ЛКС — Яндекс SmartCaptcha** (проверка скриптом с компьютера владельца: «Подтвердите, что вы не
  робот», 401 на /journal/get без входа). Капчу проходит только человек, обходить её приложение не будет.

  забирается запросами `/journal/get` без окна. Сессия закончилась (401 / страница входа) — на экране
  «Успеваемость» кнопка «Войти в ЛКС снова». Пароль приложение не хранит; оставшийся от прошлой версии стирается.
- Проверка ЛКС с компьютера: `tools/lks_check.sh` (спрашивает пароль, печатает коды ответов, без пароля и кук).
- Показ — в оформлении приложения: средний балл, оценок и пропусков всего; по дисциплинам — средний балл
  (цветом), рейтинг, пропуски и лента оценок по датам («5», «4/5», «НУ», «НН»); касание оценки — дата,
  комментарий преподавателя и задание. Новые оценки — уведомлением. «Открыть сайт ЛКС» — сайт внутри
  приложения уже со входом (куки передаются в WebView), если нужно что-то ещё.
- Moodle остаётся запасным вариантом («Другой сайт (Moodle)»).

## «Сегодня» на телефоне — новое расположение
- Сверху вниз: приветствие и дата → «Сейчас/Дальше» по расписанию (главное) → две плитки рядом: карточки
  (сколько ждут) и серия (дни подряд и неделя точками) → «Напоминания» одной карточкой с «+» в заголовке и
  тремя ближайшими → успеваемость (если подключена). Стиль прежний, плитки «проседают» с пружинкой.

## «Тихо на парах»
- Переключатель в «Настройки → Это устройство». На время пары — «Не беспокоить», после — как было.
- Сделано системным режимом (`AutomaticZenRule` «Пара», в Android 15+ — тип «по расписанию»), а не прямым
  `setInterruptionFilter`: система сама совмещает его с режимами человека, и конец пары не выключит
  «Не беспокоить», включённое вручную. Режим виден в системных настройках, там его можно донастроить.
- Пропускаются будильники, повторные звонки и звонки от избранных — чтобы не пропустить важное.
- Включение/выключение — будильником на начало и конец пары (`LessonQuiet.update`), пересчёт при каждом
  `rescheduleAll` (запуск, синхронизация, обновление расписания, перезагрузка) и при возврате в приложение.
  Перемена между парами — громко (сообщения успевают прийти).
- Нужен доступ к «Не беспокоить» (выдаёт человек в системе); без него переключатель показывает «Разрешить».
- Настройка своя у каждого устройства и не синхронизируется: на планшете она может быть не нужна.

## Будильник к первой паре
- «Настройки → Будильник к первой паре». Своё у каждого устройства (не синхронизируется), по умолчанию выключен.
- Время: крайний подъём = начало первой пары − сборы (20/30/45/60 мин) − дорога (5/15/25/40; для онлайн-пар 0).
  Будит только в дни с парами; «Не будить завтра» — в настройках и в вечернем уведомлении.
- Циклы сна (`SleepPlan`, тесты в `SleepPlanTest`): цикл 90 мин, засыпание 15 мин. За 30 минут до времени
  «лечь на 5 циклов» приходит уведомление: когда лечь на 6/5/4 цикла. Кнопка «Ложусь» запоминает время и
  сдвигает будильник на конец ближайшего цикла — только раньше крайнего времени и не больше чем на 30 минут
  (позже будить нельзя — пара). Без «Ложусь» будит в крайнее время. Фазы сна по датчикам не угадываем:
  это ненадёжно, а «100 % проснуться» важнее.
- Надёжность:
  - `AlarmManager.setAlarmClock` — системный будильник: точно в срок даже в глубоком сне телефона, значок в
    строке состояния; ставится заново при запуске, синхронизации, обновлении расписания и перезагрузке;
  - звонит сервис переднего плана (`mediaPlayback`) на потоке будильника — проходит «Не беспокоить» и «Тихо
    на парах»; громкость будильника поднимается минимум до 80 % (после — возвращается), звук нарастает 40 с,
    вибрация; мелодия — системная мелодия будильника с запасными вариантами;
  - экран будильника поверх блокировки (полноэкранное уведомление; если есть разрешение «поверх других окон» —
    открывается сразу). Если чего-то не хватает (уведомления, полноэкранный показ на Android 14+, ограничения
    батареи) — настройки показывают, что именно, с кнопкой исправить;
  - выключить — решив пример (можно отключить); «Назад» не выключает;
  - отложить — максимум 2 раза по 5 минут и только если на сборы останется ≥ 15 минут;
  - не выключил за 10 минут — пауза 3 минуты и снова, пока не начнётся пара;
  - через 3 минуты после «Встаю» — «Ты встал?»; нет ответа 2 минуты — звонок снова (можно отключить);
  - телефон был выключен в момент будильника — после включения звонит сразу (если пара ещё не началась).
- «Проверить звонок» — пробный звонок (выключается без примера, сам замолкает через минуту).

## Главная — новое расположение (телефон и планшет)

## Будильник: нельзя отключить спросонья
- Пока звонит (и до конца проверки «Ты встал?») служба специальных возможностей `WakeGuard` закрывает меню
  выключения/перезагрузки (по имени окна SystemUI или по кнопкам «Выключить» + «Перезапустить»), установщик
  пакетов (удаление), Google Play и системные настройки целиком (там «Остановить», «Удалить» и отключение самой
  службы) — жмёт «Назад»/«Домой» и возвращает экран будильника. В остальное время ничего не делает и не читает.
  Её надо один раз включить в спец. возможностях (на Android 13+ для приложения не из магазина — сначала
  «Разрешить ограниченные настройки» в сведениях о приложении); настройки подсказывают путь.
- Принудительную перезагрузку (кнопка питания ~10 с) не перехватит ни одно приложение. Поэтому состояние
  будильника перенесено в хранилище, доступное до разблокировки (`WakePrefs`, device protected storage):
  приёмник, сервис, экран будильника и защита — directBootAware. После перезагрузки (`LOCKED_BOOT_COMPLETED`)
  будильник ставится заново ещё на экране блокировки; если время прошло, а его не выключили, — звонит сразу.
  Приложение до разблокировки запускает только будильник, остальное — после `USER_UNLOCKED`.
- Отложить/выключить/«Ты встал?» не требуют расписания: время пары и подпись запоминаются вместе с будильником.
