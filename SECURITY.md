# Политика безопасности «Наставник»

## 1. Сообщение об уязвимостях

Если вы обнаружили проблему безопасности или уязвимость в приложении «Наставник», пожалуйста, не создавайте публичный issue. Отправьте отчёт через [GitHub Private Vulnerability Reporting](https://github.com/Ee1evch/touchnotes/security/advisories/new) или свяжитесь с мейнтейнером напрямую.

Каждый отчёт рассматривается в приоритетном порядке. В отчёте желательно указать:
- Версию приложения и используемое устройство/версию ОС.
- Подробное описание сценария воспроизведения (PoC).
- Оценку потенциального воздействия на пользователя.

## 2. Архитектура безопасности приложения

Безопасность приложения «Наставник» построена по принципу защиты в глубину (Defense in Depth) и строгой минимизации привилегий:

### 2.1. Аппаратное хранилище секретов (Android KeyStore)
- Все конфиденциальные данные (API-ключи LLM-провайдеров, сессионные куки ЛКС, токены синхронизации, E2E-парольные фразы) хранятся исключительно через `KeyStoreVault`.
- Используется шифрование **AES-256-GCM** с аппаратной изоляцией ключей в **TEE** (Trusted Execution Environment) или **StrongBox Keymaster** (на поддерживаемых устройствах).
- Ключи не экспортируются за пределы защищённого аппаратного чипа. Векторы инициализации (IV) генерируются аппаратно на каждый вызов шифрования.

### 2.2. Защита сетевого контура
- **Network Security Config**: открытый трафик (cleartext HTTP) заблокирован на уровне манифеста ОС (`cleartextTrafficPermitted="false"`).
- В релизных сборках доверие ограничено исключительно системным центрам сертификации (`<certificates src="system" />`). Пользовательские CA не принимаются, что предотвращает перехват трафика через установленные сертификаты.
- **NetworkPolicy (OkHttp Interceptor)**: строгий запрет открытого HTTP для внешних адресов; защита от SSRF и утечки данных во внутренние сети.

### 2.3. Изоляция и укрепление WebView
- Доступ строго ограничен доменом `https://lks.siriusuniversity.ru` по HTTPS. Любые внешние ссылки открываются в системном браузере.
- Доступ к файловой системе и контент-провайдерам выключен (`allowFileAccess = false`, `allowContentAccess = false`).
- Защита от кликджекинга и оверлеев: включён флаг `filterTouchesWhenObscured = true`.
- Защита от скриншотов и записи экрана: в релизных сборках на окне ЛКС устанавливается `FLAG_SECURE`.
- Полная очистка данных: куки, кеш, история и WebStorage стираются методом `wipeData()` сразу после завершения сессии.

### 2.4. Сквозное E2E-шифрование синхронизации
- Для синхронизации через Яндекс Диск или WebDAV поддерживается клиентское сквозное шифрование.
- Данные (снимки состояния и блобы страниц/чернил) шифруются на клиенте с помощью **AES-256-GCM**, ключ выводится через **PBKDF2WithHmacSHA256** (210 000 итераций).
- Облачный провайдер получает исключительно зашифрованные бинарные пейлоады (`SyncCrypto`).
- Приложение родителя расшифровывает снимки с помощью E2E-парольной фразы (`CloudReader`). Без фразы выводится понятная ошибка, исключая показ ложного пустого экрана.

### 2.5. Минимизация прав Яндекс Диска
- Новые подключения Яндекс Диска используют изолированную папку приложения (`app:/Nastavnik`) по протоколу Яндекс Диск REST API, без доступа к личным файлам пользователя.
- Для устаревших подключений с полным доступом ко всему диску в интерфейсе отображается предупреждение и кнопка «Переподключить».

### 2.6. Конфиденциальность данных пользователя
- Контекст диалога с нейросетью ограничен текущей сессией: при выходе из тетради контекст очищается.
- Телеметрия разметки координат (`CoordStats`) фиксирует исключительно нормализованные числовые координаты рамок без содержимого заметок и рукописного ввода.

## 3. Матрица угроз и мер защиты

| Угроза | Было | Стало | Чем проверено |
|---|---|---|---|
| Перехват открытого сетевого трафика (Cleartext HTTP Sniffing) | Разрешён любой незашифрованный HTTP-трафик во всех сборках приложения | `cleartextTrafficPermitted="false"`, `NetworkPolicy` блокирует внешний HTTP, разрешая только локальные доверенные прокси | `NetworkPolicyTest` (5 тестов в `:core`) |
| Man-in-the-Middle (MitM) атака через недоверенные пользовательские CA | Доверие пользовательским сертификатам в релизе | В релизе доверие строго системным CA (`<certificates src="system" />`) | Аудит `network_security_config.xml`, `NetworkPolicyTest` |
| Утечка заметок и оценок при компрометации облачного хранилища | Данные синхронизации (заметки, тетради, оценки) хранились в открытом архиве gzip на Диске | Клиентское сквозное шифрование AES-256-GCM с PBKDF2 (210 000 итераций). Облако видит только шифрованный конверт | `SyncCryptoTest`, `SyncEngineTest`, `CloudReaderTest` |
| Чрезмерные привилегии токена доступа к Яндекс Диску | Запрос полного доступа ко всем файлам и папкам Диска (`disk:/`) | Доступ сужен до изолированной папки приложения (`app:/Nastavnik`); для старых токенов показывается предупреждение и кнопка «Переподключить» | `YandexDiskStoreTest`, UI-тесты настроек |
| Кликджекинг, перекрытие окон и инъекция в WebView авторизации ЛКС | Стандартный WebView без проверки перекрытия и с неограниченной навигацией | Включён `filterTouchesWhenObscured = true`, белый список хостов Сириуса, открытие внешних ссылок в браузере ОС | `LksScreenTest`, ручная проверка входа в ЛКС |
| Утечка сессионных кук ЛКС через кеш или постоянную память WebView | Сессионные куки оставались в кеше и хранилище WebView между сессиями | Метод `wipeData()` стирает куки, кеш, историю и WebStorage; окно защищено `FLAG_SECURE` | `LksExtractTest`, аудит жизненного цикла `LksWeb` |
| Извлечение API-ключей LLM и паролей из хранилища устройства | Ключи и пароли хранились в открытом виде в SharedPreferences | `KeyStoreVault`: аппаратная изоляция в TEE / StrongBox (AES-256-GCM), защита от потери при отсутствии StrongBox | `KeyStoreVaultTest`, `SettingsRepoTest` |
| Подмена APK при автоматическом обновлении (MitM / Forged APK) | Открытие ссылки на скачивание без проверки контрольной суммы и подписи | Скачивание строго по HTTPS с репозитория, проверка SHA-256 хэша и сверка сертификата подписи через `ApkTrust` | `ApkTrustTest` (6 тестов) |
| Публикация недоверенной или неподписанной релизной сборки в CI | Релиз публиковался на каждый push, подписывался debug-ключом при отсутствии секретов | Изолированный job `publish`, обязательные секреты `RELEASE_KEYSTORE_*`, сверка SHA-256 отпечатка через `EXPECTED_RELEASE_CERT_SHA256`, очистка keystore по `trap EXIT` | `.github/workflows/build.yml` |
| Накопление и утечка личного контекста студента в модель нейросети | История диалога сохранялась между сессиями тетради | Сессионная изоляция контекста: при закрытии тетради контекст очищается | `CleanSessionTest`, `MentorSessionTest` |
